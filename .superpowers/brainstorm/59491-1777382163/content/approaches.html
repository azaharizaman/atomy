Design Approaches for AI Insights & Governance

Choose the architecture pattern for Plan 5 alpha slice

A

Unified InsightOperations Coordinator

Single InsightCoordinator in InsightOperations handles all narrative types (dashboard, RFQ, governance, reporting). One provider client per capability group. Cache keyed by narrative type + entity ID.

Pros: Simple, consistent, one workflow. Easy to audit.

Cons: Coordinator grows large; mixing unrelated narrative logic.

B

Per-Surface Coordinators (Recommended)

Four focused coordinators: DashboardInsightCoordinator, RfqInsightCoordinator, GovernanceNarrativeCoordinator, ReportingSummaryCoordinator. Each owns its DTO, cache key, and invalidation logic. InsightOperations aggregates.

Pros: SRP, testable, clear ownership, scalable.

Cons: More files, more contracts to define.

C

Domain-Delegated with InsightOperations Aggregation

RFQ insights live in QuotationIntelligence orchestrator. Governance narratives live in ComplianceOperations. InsightOperations only aggregates results for cross-cutting dashboard/reporting summaries.

Pros: Domain logic stays close to source data.

Cons: Harder to track AI capability groups; inconsistent narrative patterns; more orchestrators to update for provider changes.

My recommendation: B — per-surface coordinators keep InsightOperations cohesive without becoming a god class, and each coordinator maps cleanly to one capability group for provider routing and feature-flag gating.
